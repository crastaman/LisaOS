# Examples

`sample_bundle.json` is **synthetic** — generated by calling
`core.decision_bundle_exporter.build_bundle()` against hand-written
fixture evidence, not real telemetry from `~/Lisa/reports/lisa/`. It
exists to make `01_DECISION_BUNDLE_SPEC.md` concrete: every field the
schema supports is populated (participating workers, an unacknowledged
governance violation, proposed actions, the `gaps` list) so a reader can
see the real shape without needing a live LisaOS run.

Regenerate it with `core.decision_bundle_exporter.build_bundle()` directly
(not the CLI, which reads real `reports/lisa/` data) if the schema
changes — see the generation snippet in Phase C1's implementation report
in `CHANGELOG.md`.

## `sample_brief_degraded.json`

**Real, not staged.** Generated by calling
`advisors.gpt_advisor.generate_brief()` on `sample_bundle.json` with the
real (uninjected) `call_chat_completion` — no `LISA_CONSOLE_OPENAI_API_KEY`
is configured anywhere in this environment, so this genuinely exercises
the fail-closed degraded path, not a simulation of one. This is what every
Executive Brief looks like today, until a key is configured.

## `sample_brief_ok.json`

**Illustrative, hand-written** — not a live model output (no credential
is configured to produce one). Shows what a successful brief's shape and
tone should look like once Phase C2 has real API access: all fields
populated, grounded in `sample_bundle.json`'s specific evidence rather
than generic placeholder text. Useful for reviewing the schema and the
expected tone (`docs/GPT_CONTEXT/03_ROSHAN_PREFERENCES.md`) without
needing a real API call.

## `sample_notification_payload.json` / `sample_notification_payload_degraded.json`

**Real** — both generated by calling `advisors.notify.build_payload()`
(the actual allowlist-construction code, not hand-written) against
`sample_brief_ok.json` and `sample_brief_degraded.json` respectively,
with an illustrative placeholder `base_url`. Note everything the payload
does *not* contain compared to the source brief: no `summary`, no
`key_risks` detail, no `bundle_id`, no evidence — only the seven
allow-listed fields documented in `03_NTFY_NOTIFICATION_SPEC.md`. Neither
file was sent to a real ntfy server — `build_payload()` does no network
I/O, it only constructs the dict that a subsequent `send_notification()`
call would transmit.
