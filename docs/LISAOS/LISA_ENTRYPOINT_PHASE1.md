## What `lisa` does

`bin/lisa` is the single authoritative entrypoint for natural-language missions in LisaOS.
It classifies every mission deterministically (no LLM, no heuristics) and routes it to
exactly one of three outcomes:

| Outcome | Meaning | Exit |
|---|---|---|
| **BLOCKED** | Mission cannot be routed (empty input, etc.) | 5 |
| **DIRECT** | Conversational/explanatory — Phase 1 does not execute these | 0 |
| **GOVERNED / PLANNING_REQUIRED** | Structural work; a WorkPackage graph is required | 4 |
| **GOVERNED / dispatched** | Valid `--goal` file provided; routes to `lisa-dispatch` | 0/2/3 |
| **GOVERNED / VALIDATION_FAILED** | `--goal` file failed graph validation | 6 |

---

## Classification rules

Rules are evaluated in order. GOVERNED rules short-circuit D rules.

| Rule | Pattern | → |
|---|---|---|
| `B1_EMPTY_MISSION` | Empty or whitespace-only mission | BLOCKED |
| `G5_SPRINT_REFERENCE` | `S0\d\d`, `WP-\d+`, `sprint`, `LISA-I\d+` | GOVERNED |
| `G1_REPO_WRITE` | implement, write, edit, create, delete, patch, commit, refactor, fix, modify, migrate, deploy, install, upgrade, rename | GOVERNED |
| `G2_EXECUTION_MUTATION` | run tests, build, execute, exec, insert, update, drop, alter, truncate, wp-cli, migration | GOVERNED |
| `G3_WORK_TYPE` | audit, production-readiness, production readiness, readiness review, independent review, architecture decision, security review, release, benchmark, investigation | GOVERNED |
| `G4_MULTI_DOMAIN` | ≥3 distinct domain nouns from: lifecycle, permission, notification, payment, test, booking, appointment, schema, migration, api, capacity, evidence, report, review | GOVERNED |
| `D1_EXPLANATORY` | explain, what, how, why, describe, summarize/summarise, show, list, status, help (no G signals present) | DIRECT |
| `DEFAULT_GOVERNED_AMBIGUOUS` | Nothing matched | GOVERNED |

All applicable G rules are collected and reported. ANY G match → GOVERNED (D rules cannot override).

## PLANNING_REQUIRED contract

When classification is GOVERNED and no `--goal` is provided:

```
Classification : GOVERNED
Status         : PLANNING_REQUIRED
Reason         : mission requires a validated WorkPackage graph
Next command   : lisa "<mission>" --goal <goal.json>
```

Exit 4. No execution occurs. The caller must produce a goal file and re-invoke.

## CLI

```
lisa "<mission>" [--goal PATH] [--json] [--simulate] [--intake-path PATH]
```

- `--goal PATH` — path to a JSON array of WorkPackage objects (validated before dispatch)
- `--json` — output structured JSON instead of human-readable text
- `--simulate` — forwarded to `lisa-dispatch`; no real agent spawn, no spend
- `--intake-path PATH` — override intake ledger path (test seam only)

---

## Intake evidence

Every invocation appends one or more records to `reports/lisa/orchestration/intake.jsonl`:

```json
{"request_id": "<uuid4>", "timestamp": "<UTC ISO8601>", "mission": "...",
 "classification": "GOVERNED", "matched_rules": [...], "reason": "...",
 "status": "PLANNING_REQUIRED|DIRECT_INFO|BLOCKED|VALIDATION_FAILED|DISPATCHED|DISPATCH_COMPLETED",
 "goal_path": null, "goal_package_ids": null, "validation_errors": null,
 "dispatch_exit_code": null}
```

`DISPATCHED` and `DISPATCH_COMPLETED` share the same `request_id`.  
The ledger is append-only; records are never rewritten.

## Installing on PATH

`bin/lisa` is not installed to PATH by default.  To invoke it as a bare `lisa`
command, create a symlink in a directory that is already on your PATH:

```bash
ln -s ~/Lisa/bin/lisa /usr/local/bin/lisa
```

Once the symlink is in place, the `Next command` hint in `PLANNING_REQUIRED`
output will print the bare `lisa` name instead of the full invocation path.
Do **not** copy the file — a symlink ensures the live source is always used.

## Phase 1 limitations (honest scope)

- **DIRECT missions are not executed.** The honesty statement is printed; no chat subsystem exists.
- **No NL planner.** `bin/lisa` cannot synthesize a goal file from a mission; the caller must produce one externally.
- **No synthesizer.** Goal JSON must be hand-authored or generated by a future Phase 2 planner.
- **`bin/lisa-legacy`** — the v0.1 registry runner (`lisa list`, `lisa run <task>`) is preserved at `bin/lisa-legacy` and is unmodified.
